Extended coding benchmark - Inkling 2 Mini reasoning levels vs Gyro-S medium
Date: 2026-11-24
Harness: Panda Engine, Python functions and bug-fixes graded by execution

This extended report supersedes the preliminary single-pass comparison in
BENCHMARK-coding-ink-vs-gyro.txt for accuracy conclusions. Gyro-S was tested
ONLY at medium, as requested. Ink artifact: Q2_K_XL. Ink requests used
reasoning_effort low/medium/xhigh/max; all variants had the same 30 tasks,
4 generated solutions per task. Gyro medium used the same tasks and tests.

METHOD
------
- 30 Python tasks: 20 function implementations and 10 bug fixes.
- 4 independent model outputs per task and per condition: 120 task-runs and
  120 API requests per condition; 600 requests total (4 Ink conditions plus
  Gyro medium).
- Each answer was saved as Python and executed against fixed tests. Score
  reports both whole-task pass (every case must pass) and individual cases.
- Each request used max_tokens=8192, no temperature override.
- One additional six-snippet OK/BUG reviewer probe was run once per condition.
  It was separate from the 30-task repeated coding score.
- The benchmark elapsed times below sum model-request wall time; model
  switching/loading and analysis are not included.

INTERPRETATION
--------------
- On these 30 short, self-contained Python tasks, Ink low, medium and xhigh
  tied exactly at 116/120 task-runs and 576/580 test cases. The extra
  reasoning of medium/xhigh produced no observed accuracy gain over low.
- Ink max was slightly worse (114/120) and also consumed more time/tokens
  than low.
- Gyro medium scored 115/120, one fewer passed output than the three tied
  Ink variants, and 575/580 cases. The sample is too small to call that a
  meaningful intelligence difference. In this test, low was sufficient to
  match Ink medium/xhigh; this does NOT establish that low is sufficient for
  large repository-level coding or difficult independent review.
- Gyro used less output (22,165 tokens vs Ink low's 34,930) and finished
  sooner in aggregate. Ink decode was faster per token: ~113.5-142.5 tok/s
  across variants vs Gyro ~87.6 tok/s by aggregate wall time. Token count and
  request complexity affect end-to-end time; do not read tok/s as quality.
- The reviewer probe showed the same miss for all conditions, so there is no
  observed reviewer advantage for more Ink reasoning or Gyro medium here.

LIMITATIONS / ACCURACY CAVEATS
------------------------------
This is a fixed, small benchmark of short functions, not a real repository
patch benchmark. Four generations per task are repeated samples, not 120
independent task types. The tests are deterministic but not exhaustive; the
count_vowels prompt/test may be underspecified about accented vowels, and
only failures are summarized here (generated code and per-request transcripts
were not persisted). The one-shot reviewer probe is too small to estimate
review quality. Results support the narrow statement that Ink low matched
Ink medium/xhigh on this suite, not a general claim about coding ability.
